# Product depth milestone

Continued from `main` at `18a2978` without replacing the Expo Router, Fastify, PostgreSQL, WebSocket, versioned mutation or offline queue architecture. This is a substantial development milestone, not a production-readiness declaration.

## Functionality added

- **Reports:** household-local today, seven-day, thirty-day and custom inclusive date ranges (bounded to approximately one year); all-child or single-child selection; selectable sleep, feeding, diaper/potty, medicine, symptoms, temperature, growth and routine sections. Daily charts show real entry counts by section or completed sleep hours. Summaries separate quantities by unit and substance, show recorded temperature/growth ranges and recent observations, and never treat missing entries as proof of no care. Overlapping sleep is counted once and clipped at calendar boundaries, including daylight-saving changes.
- **Pediatrician export:** HTML print layout with child/date/section selection, caregiver attribution, optional private notes, explicit caregiver-entered-information labeling and a nonmedical disclaimer. Web opens a separate print preview; choose Save as PDF. Native uses Expo Print and Sharing, and removes the temporary file after sharing finishes. CSV remains available and explicitly includes notes. Local pending/conflicting changes are labeled in the PDF. Exported copies are outside app access controls.
- **Routine Intelligence:** recency-weighted recorded intervals; age changes the recency half-life, not an assumed medical schedule. Nap estimates use wake-to-nap history; bedtime uses local-clock observations around midnight. Predictions expose variability windows, sample counts, bounded heuristic confidence, recent drift and typical recorded nap duration. Ongoing timers, sparse data and stale estimates suppress predictions. Existing sibling overlap logic is preserved. Confidence is not a calibrated probability.
- **Natural-language drafts:** all existing categories, named children and sibling groups, durations, relative times, AM/PM clock times in the supplied timezone, offset-bearing timestamps, quantities/units and notes. Examples: `River had a 4 oz bottle`, `River and Sage: nursed both for 15 minutes 30 minutes ago; notes: Settled well`, `temperature 37 C forehead`, `medicine Example 2 ml`, `wet diaper yesterday at 10 am`. Ambiguous names/times and unsupported phrases return no draft. Parsing is deterministic and local behind an exported interface; no model key is needed. The editable review form is always required before saving.
- **Account access:** public recovery/reset/verification screen around existing single-use token endpoints. Missing email delivery is reported honestly. Invitation links open a join screen; the server still requires the invited email. Native links use `EXPO_PUBLIC_WEB_URL` when supplied, otherwise the `nestwise://` scheme.
- **Privacy:** authenticated household/user JSON exports; typed owner-only household deletion; typed, version-checked owner-only child deletion; password-confirmed account deletion after leaving every household. Child erasure also removes associated shared sibling events/reminders and historical sync payloads; a minimal event-ID marker prevents stale offline mutations from resurrecting erased care. Account deletion removes login identity, sessions, recovery tokens and invitations; shared care stays with remaining caregivers under `Former caregiver` attribution and anonymous audit references. Stable event/actor IDs and free-text mentions can remain in shared care.
- **Native local protection:** care caches and account metadata use XChaCha20-Poly1305 through `@noble/ciphers`, fresh Expo Crypto nonces, storage-key binding, and per-account keys in Expo SecureStore. Legacy plaintext migrates when read. Missing/corrupt keys fail visibly and never overwrite saved encrypted data. Sign-out removes cache keys after clearing data. Browser caches remain unencrypted. This is not end-to-end encryption or protection against a compromised unlocked device.
- **Consumer UI:** calendar selection alongside keyboard date/time input, richer child profile editing, recorded-care dashboard totals, collapsible report options, link-based invitations, and reduced excess space in the mobile overview. Existing sage/cream/lavender styling and responsive navigation are preserved.
- **Development fixtures:** `node --env-file=.env scripts/seed-fictional.mjs` creates a clearly labeled fictional twin household with 649 events across three weeks. It refuses production mode or nonlocal API hosts. Credentials are saved only in ignored `.local/fictional-seed.json`. `node scripts/visual-review.mjs` captures seven screens at 390x844, 412x915, 768x1024, 1366x768 and 1920x1080 using that fixture. Run this separately from E2E to avoid sharing the local API rate-limit budget.

## Remaining limitations and release blockers

- Native PDF sharing, keychain lifecycle, calendar modal behavior, screen-reader interaction, notifications and background/foreground behavior still need real iOS/Android device testing. Bundle export does not verify these capabilities. A device restore without its device-only key cannot recover encrypted offline records; use a deliberate export before migration.
- Web uses the browser print dialog, not an automatic PDF download. Print pagination depends on the browser/platform. Abrupt termination while preparing a native PDF can leave a temporary plaintext cache file; normal completion removes it. Review exports before sharing.
- The parser is a documented local grammar, not unrestricted language understanding or multi-event prose extraction. Unsupported wording remains editable through the structured form. AM/PM ambiguity at the repeated DST hour requires an explicit offset. Day-of-week personalization and statistically validated time-of-day submodels are not implemented; the current confidence score is descriptive, not clinically or statistically calibrated.
- Permanent child deletion removes shared entries for siblings too; archive instead to preserve them. Offline devices, exported files and database backups cannot be remotely erased. Stale pending edits to erased events remain visible on their originating device instead of silently disappearing. Settings provides an explicit confirmation to discard held edits after reviewing/exporting them, allowing later queued care to synchronize. There is no automatic import into a replacement event.
- Server exports reflect currently authorized data and omit credentials/internal mutation machinery. Removed-household data is only available in an existing local backup. Shared free-text notes can retain identifying mentions after account deletion. Backup retention, legal/privacy policy, restoration procedures and independent security review remain release work.
- Email delivery still requires a real `AccountMail` adapter supplied to `buildApi`. No production adapter or delivery provider is configured. Hosting must redact recovery/invitation query tokens from access logs and analytics, use HTTPS, private database networking and appropriate secret management. The local static server now sends no-referrer, nosniff and frame-denial headers; it is not a production host.
- Initial household loading still uses a full snapshot; reconnect changes remain bounded/incremental. Very large server exports are not streamed. Browser storage is unencrypted, and native encryption cannot protect an unlocked compromised device, screenshots or deliberately shared files.
- Dependency audit still reports 18 moderate findings through Expo/navigation tooling. `decode-uri-component` 0.4.1 is ESM while inherited `query-string` 7 expects CommonJS; blindly overriding it is unsafe. A targeted UUID 11.1.1 override did not replace installed UUID 7.0.3 and was removed rather than presented as a fix. Automatic approval review blocked removal of two generated dependency folders to force re-resolution, with no reason beyond "blocked by policy." No incompatible Expo downgrade or force-audit fix was applied.

No deployment, store submission, medical validation or production-readiness claim is part of this milestone.
