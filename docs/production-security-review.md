# Focused production security review — September 7, 2026

Repository review and local tests, not an independent penetration test or compliance certification. No live infrastructure exists for this review. Existing authorization/realtime/offline architecture is preserved.

| Area | Reviewed controls / changes | Remaining risk or release work |
| --- | --- | --- |
| Authentication / sessions | Salted scrypt password hashes; random 256-bit Bearer tokens hashed in DB; expiry/revocation; password reset revokes sessions | No MFA or breached-password service; bearer token compromise grants access until revocation/expiry; web sessionStorage is accessible to same-origin script |
| Authorization / household isolation | Parameterized household-scoped queries; role guards; mutation transactions recheck membership/session under household lock; current isolation/conflict tests pass | Application authorization, not PostgreSQL row-level security. Not every administrative read/write uses the same transactional recheck; concurrent revocation races warrant a dedicated review before high-risk use |
| Realtime | Exact browser origins; first-frame token; 5-second auth deadline, 2 KB payload cap; access rechecked on pushes/heartbeats; 500 connection admission ceiling; no care data in notifications | Real host proxy/reconnect/load behavior unverified; connection ceiling is not a substitute for upstream DDoS protection |
| CORS / proxy | Every allowlist entry validated, no wildcard, HTTPS in production; bounded explicit proxy hops | CORS is a browser control, not authentication; native/no-Origin clients still use tokens. Validate actual Render forwarded-header chain and spoof resistance |
| Rate limiting | Existing global 200/min and tighter auth/account endpoint IP limits retained; readiness excluded | Per-process in-memory limits reset at deployment and are not shared across replicas; no persistent account-based throttle. Start single-instance; review abuse protection before scaling |
| Security headers / caching | API Helmet + no-store; static CSP/frame denial/no-referrer/nosniff/HSTS; no cached auth/export bodies; local browser journeys exercise headers | CSP connect-src currently allows HTTPS/WSS broadly; narrow after domains are known. Provider response headers still need external smoke tests |
| Secrets / logs | API production commands no longer read .env; URL/TLS/env validation; startup and request errors omit raw messages/payloads; no secrets in public build configuration | Provider access/DB slow-query/mail logs are outside application redaction; restrict access and retention. No complete historical secret scanning certification |
| Recovery / verification | Environment-selected Resend boundary; HTTPS trusted web origin; code absent from generated email URL; timeout/idempotency/acceptance validation; failed issue removes token; tests use fake HTTP transport only | No actual email delivery tested. Verification is not enforced for account use. Timing/provider errors can disclose account existence. No durable mail outbox/bounce handler; occasional delivery failure requires retry |
| Destructive privacy | Existing password/typed confirmations, owner transfer/leave safeguards, household/child authorization and erasure markers preserved | Deletion is not remote wipe of offline devices, exports or backups; historical UUID/free-text attribution limitations remain; review backup retention and restoration against erasure obligations |
| Exports / files | Authorized DB exports exclude auth secrets; escaped PDF HTML and spreadsheet formula handling; PDF notes excluded by default; local-only generation/sharing | Exported files are plaintext under user control; native crash may leave temporary PDF. No access revocation after export; do not market as a medical record |
| SQL / database | Parameterized access; bounded pg pool; explicit verified external TLS or acknowledged private transport; checksum ledger/advisory lock/atomic non-seeding migration; no destructive reset | Internal Render transport is not asserted TLS. Runtime and migration initially share DB role; use separate least-privilege role in a subsequent audited setup. Large exports/full bootstrap snapshots and retained sync history need capacity/retention review |
| Client storage | Native cache encryption and device-bound keys retained, tested at library boundary; no automatic pending-edit deletion | Web cache unencrypted, vulnerable to same-origin compromise/local access; key loss/device restore may make native unsynced cache unrecoverable. Device QA outstanding |
| Dependencies | Lockfile installation and complete tests rerun; no forced Expo downgrade or unsafe override applied | 18 moderate audit entries via decode-uri-component/query-string/navigation/Expo and uuid/xcode. Zero high/critical in current audit does not establish absence of vulnerabilities |

The two underlying advisories returned by the local audit are [decode-uri-component denial of service](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr) and [uuid buffer bounds](https://github.com/advisories/GHSA-w5hq-g745-h8pq). Transitive packages account for the remaining entries. Treat them as unresolved; dependency upgrade work needs compatibility testing. The earlier blocked dependency-folder deletion was not retried or worked around in this milestone.

For an initial controlled staging deployment, use only fictional test data, restrict who can use it, and complete the operational/security gates in [the deployment guide](production-deployment.md). Public collection of real family data still requires an explicit risk decision and a suitable privacy/retention policy.
